Coerenza GeograficaPUNTO-NEL-POLIGONO

Un evento non appartiene a un comune perché il nome combacia, ma perché le sue coordinate cadono dentro i confini reali del territorio. La geografia decide, non la stringa.

Stato
ATTIVO
Funzione
valida_coerenza_geografica_v2
Motore
PostGIS · ST_Contains
Copertura
31 comuni · Provincia di Latina
Il problema

Perché il nome non basta

Il vecchio controllo di coerenza territoriale confrontava il nome del comune estratto dall'evento con i nomi nel registro dei territori. Funziona finché i dati sono puliti, ma è cieco rispetto a due errori reali: un evento attribuito al comune sbagliato passa il controllo se il nome combacia, e una frazione condivisa tra più comuni non viene mai distinta.

La soluzione carica i confini ufficiali ISTAT (poligoni) di tutti i comuni nel database e verifica geometricamente se le coordinate dell'evento cadono dentro il territorio dichiarato. La verità diventa la mappa, non l'etichetta.

La logica

Tre esiti, non un sì/no

Un confine netto produce falsi positivi: un evento sul molo di un'isola cade tecnicamente fuori dal poligono costiero pur essendo legittimo. Una tolleranza fissa, al contrario, maschera gli errori veri. La funzione risolve distinguendo perché un punto è fuori, non solo quanto.

COERENTE
Il punto cade dentro il poligono del comune attribuito. Coerenza territoriale piena, nessuna tolleranza necessaria.
COERENTE_BORDO
Il punto è fuori dal poligono ma non cade dentro nessun altro comune (mare, costa, montagna) ed è entro 500 m dal confine. Caso tipico delle isole e delle frazioni costiere: l'evento è legittimo, la coordinata è solo imprecisa.
ERRORE_ATTRIBUZIONE
Il punto cade dentro un comune diverso da quello dichiarato. Non è imprecisione: l'evento è attribuito al territorio sbagliato. Il sistema lo segnala con il nome del comune reale, senza mascherarlo.
Principio chiave: non conta quanto un punto è fuori dal confine, ma se "ruba" il punto a un altro comune valido. La distanza è ambigua; l'appartenenza a un altro poligono no.
Caso reale

Doganella di Ninfa vs Ponza

Al primo passaggio sui 66 eventi geolocalizzati, 8 risultavano fuori dal proprio poligono. La distanza dal confine era quasi identica (Doganella a 362 m, Ponza-Le Forna a 350 m): una soglia di metri non li avrebbe mai distinti. La logica a tre esiti sì.

Implementazione

La funzione

create or replace function valida_coerenza_geografica_v2(
    p_lat double precision, p_lng double precision, p_territorio_id integer
) returns text as $$
declare
    v_punto geometry; v_poligono geometry; v_altro text;
begin
    v_punto := ST_SetSRID(ST_MakePoint(p_lng, p_lat), 4326);
    select geom into v_poligono from territori where id = p_territorio_id;
    if v_poligono is null then return 'NO_GEOM'; end if;

    -- A) dentro il comune attribuito
    if ST_Contains(v_poligono, v_punto) then return 'COERENTE'; end if;

    -- B) dentro un ALTRO comune -> errore di attribuzione
    select t2.nome into v_altro from territori t2
      where t2.id <> p_territorio_id and ST_Contains(t2.geom, v_punto) limit 1;
    if v_altro is not null then return 'ERRORE_ATTRIBUZIONE:' || v_altro; end if;

    -- C) fuori da tutti, ma entro 500m -> caso-confine
    if ST_DWithin(v_punto::geography, v_poligono::geography, 500) then return 'COERENTE_BORDO'; end if;

    return 'FUORI_AREA';
end; $$ language plpgsql;
FONTE CONFINI: dati ufficiali ISTAT (openpolis/geojson-italy), 31 comuni Provincia di Latina, MULTIPOLYGON SRID 4326, semplificati a ~50 m. Caricati in territori.geom dopo la correzione di 8 codici ISTAT errati.
Ruolo nella pipeline

Questa funzione è l'evoluzione del Pilastro I — Coerenza Territoriale del T.C.F. dentro BORGOVIA. Sostituisce il match per nome con la verifica geometrica reale. Un evento COERENTE o COERENTE_BORDO supera il pilastro; un ERRORE_ATTRIBUZIONE viene segnalato per revisione, con indicato il comune corretto. La geografia non è più un'etichetta da fidarsi: è una verifica che si può eseguire.
